# AI evaluation

Generated by `node src/ai/eval.mjs` on 2026-10-18. All data is synthetic.

## Method

- Golden cases live in `tests/fixtures/ai/golden/*.json`, one file per task. Each case has an `input`, an `expected` block, optional `pii` strings that must never reach a cloud provider, and optional `recorded` responses for the vertex providers.
- Every provider call goes through `guard()` in `src/ai/guardrails.mjs`: injection markers are neutralised, input is capped, cloud providers receive redacted text, and outputs are validated against `src/ai/schemas.mjs`. An invalid output counts as a fallback and scores as an empty prediction.
- The local rules provider runs for real. The vertex providers are never called: their responses are replayed from the recorded fakes in the golden files, so results are fixed and say nothing about live model quality.
- Set metrics (extraction, photo damage areas, next best actions) are micro-averaged over `name=value` facts: precision is correct facts over predicted facts, recall is correct facts over expected facts. Narrative scoring also counts the `cues` list. Empty values and `unknown` are not predictions.
- Severity is scored on band accuracy (exact, and within one band). Fraud is scored on the flag (score >= 40) plus indicator precision and recall. Subrogation is scored on the flag. Summaries are scored on how many required key facts appear.
- `Cases` is the number of golden cases scored for that provider; `Fallbacks` counts calls that returned no usable output (refusal or invalid), of which `Invalid` failed schema validation.

## Tenant AI settings

Read from the tenant config `ai` block on every `ai.run`. Callers should pass `claimId` in the run options.

- `ai.humanConfirmRequired` (boolean). When `true`, every `cascade.run` result carries `unconfirmed: true`, including early returns where confidence cleared the threshold. When `false` or absent, behaviour is unchanged.
- `ai.redactPiiBeforeModel` (boolean). Cloud providers always receive redacted input (default `true`); an explicit `false` is honoured for the local provider only and never lowers cloud redaction. An explicit `true` also redacts input for the local provider and for injected (unguarded) providers; placeholders are restored in the returned output.
- `ai.maxTokensPerClaim` (number). Tokens per claim are summed from `ai_inference` rows for the tenant whose `usage.claimId` matches (`inputTokens + outputTokens`; the claim id is stored inside the usage JSON, there is no schema change). Once the total reaches the limit, cloud entries are skipped and logged with `usage.skipped = 'budget'`, the local provider is used, and the result has `unconfirmed: true`. Counts are per tenant; another tenant's usage is never included. Without a `claimId` the budget is not enforced.

## Limits

- Golden sets are small and written for this proof of concept; treat the numbers as regression guards, not benchmarks.
- Recorded vertex responses are hand-written to exercise scoring and the guardrails, including one deliberately invalid reply.
