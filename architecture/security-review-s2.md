What matters most:

1. **Tenant isolation held.** Tenant B tokens got 404 or 403 on every tenant A claim, document, webhook, intake, triage, routing, adapter and adjuster route probed. A body `tenantId` and `X-Tenant-Id` from a non-admin are refused. Modules in scope use `ctx.db` of the tenant-bound ctx only (no `raw`, `system`, `forTenant` for tenant data, and no 4-argument `bus.publish`).
2. **The worst gaps are inside one tenant**: role scope (SEC2-001 intake `agent`, SEC2-003 fake core, SEC2-004 claimant sees fraud data), plaintext PII at rest (SEC2-002), and three one-request availability attacks that stall the single-threaded server for every tenant (SEC2-005, SEC2-006, and tenant-authored regexes SEC2-013/014).
3. **AI layer**: outputs are only shape-checked at the top level (SEC2-009), one caller skips tenant attribution (SEC2-010), and claimant-uploaded documents become "accepted facts" without review (SEC2-012). Triage clamps what it consumes, which limited the blast radius.

## 2. Method

- Read every file in scope, then probed running code with scratch scripts (boot via `tests/security/helpers.mjs`, real seed tenants `aurelia-mutual` and `kestrel-point`). A finding is "Verified" only if a script reproduced it; otherwise "Suspected".
- Eight checklist areas per target: **A1** tenant isolation, **A2** RBAC against `x-roles` and object-level access (IDOR), **A3** PII (encrypted, absent from events, logs, errors, AI inference log), **A4** prompt injection (delimiting, schema validation, no privilege decisions), **A5** webhooks and SSRF, **A6** uploads, **A7** error leakage, **A8** devMode and dev-login exposure.
- Role drift against OpenAPI was computed by script (registered `opts.roles` vs `x-roles`). Differences: `carrier_admin` alias on the config, integrations, routing and intake routes (legacy name of `tenant_admin`, now both are in `ROLES`), plus the real deviations `agent` on five intake routes and `config/public` (SEC2-001), and `integration` on `GET /claims/{id}/coverage`.
- Regression tests: `tests/security/sec2-rbac-pii.test.mjs`, `sec2-availability-ai.test.mjs`, `sec2-webhooks.test.mjs`, helper `sec2-helpers.mjs`, and three `import()` lines appended to `tests/security/index.js` so `node --test tests/security/` loads them. Tests named `SEC2-NNN` assert the secure behaviour and call `t.todo(...)`: they run, fail today, and are reported as TODO. When a fix lands the test passes and the `t.todo` line should be deleted.

## 6. Controls verified working (regression guards in the tests)

- Tenant isolation matrix of 14 cross-tenant routes plus body `tenantId` and `X-Tenant-Id` abuse (`sec2: tenant B cannot read...`).
